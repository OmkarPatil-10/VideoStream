# VideoStream — Backend

This repository contains the backend for the VideoStream project: a Node.js + Express API using MongoDB for persistence and Cloudinary for media storage. It implements user authentication (JWT), video upload/management, comments, likes, subscriptions, playlists and basic dashboard endpoints.

## Quick Summary
- Runtime: Node.js (ES modules)
- Frameworks: Express, Mongoose
- Auth: JWT (access token via cookie or `Authorization: Bearer ...` header)
- Media: Cloudinary (uploads and deletes)

## Requirements
- Node.js 18+ (or compatible)
- MongoDB instance
- Cloudinary account (for production media uploads)

## Environment
Copy `.env.sample` to `.env` and set the values.

Key variables (see `.env.sample`):

- `PORT` — port to run server (default 3000)
- `MONGODB_URI` — MongoDB connection URI (without DB name)
- `DB_NAME` — database name (defined in `src/constant.js`)
- `ACCESS_TOKEN_SECRET`, `REFRESH_TOKEN_SECRET` — JWT secrets
- `ACCESS_TOKEN_EXPIRY`, `REFRESH_TOKEN_EXPIRY` — token expiry (e.g. `1d`)
- `CLOUDINARY_CLOUD_NAME`, `CLOUDINARY_API_KEY`, `CLOUDINARY_API_SECRET`

## API Overview
Base path: `/api/v1`

Authentication
- Protected routes expect a valid access token either in the `accessToken` cookie or the `Authorization: Bearer <token>` header. The `verifyJWT` middleware enforces authentication.

Important resource endpoints (high level):

- Users: `/api/v1/users` — registration, login, profile, refresh tokens (see routes for details)
- Videos: `/api/v1/videos` — protected; supports:
	- `GET /api/v1/videos` — list published videos, supports `page`, `limit`, `query`, `sortBy`, `sortType`, `userId`
	- `POST /api/v1/videos` — upload a video (multipart). Fields:
		- `videoFile` (file) — video file
		- `thumbnail` (file) — thumbnail image
		- `title`, `description` (body fields)
	- `GET /api/v1/videos/:videoId` — get video by id (increments view count)
	- `PATCH /api/v1/videos/:videoId` — update (owner only); accepts `thumbnail` file and/or `title`/`description`
	- `DELETE /api/v1/videos/:videoId` — delete (owner only)
	- `PATCH /api/v1/videos/toggle/publish/:videoId` — toggle publish status (owner only)

- Tweets, Subscriptions, Comments, Likes, Playlists, Dashboard, Healthcheck: each has its own route under `/api/v1/<name>`; refer to `src/routes` for concrete endpoints and required payloads.

Note: The `videos` routes apply `verifyJWT` for all endpoints in `src/routes/video.routes.js`.

## File Uploads
- File uploads use `multer` middleware and save temporary files under `public/temp` before uploading them to Cloudinary via `src/utils/cloudinary.js`.
- After successful Cloudinary upload the local temp file is removed.

## Database & Pagination
- Mongoose is used for models. The `Video` model includes fields for `videoFile`, `thumbnail`, `owner`, `isPublished`, `views`, etc.
- Aggregation pipeline is used for listing videos with lookup to `users` collection and pagination logic handled via `page`/`limit` query params.

## Notes & Gotchas
- Environment file must be named `.env` at the repo root of the Backend folder (the app loads `./.env`).
- JWT verification reads token from `cookies.accessToken` or `Authorization` header.
- Cloudinary credentials are required for upload/delete functionality.

## Development Tips
- Keep uploads small while testing; production media should be uploaded to Cloudinary.
- Use MongoDB Atlas or a local MongoDB with the proper `MONGODB_URI`.
